

# SITA OS — Full Audit & Deployment Readiness Plan

## Summary

After a thorough audit of the entire codebase, SITA OS is structurally very complete. The project has 150+ routes, 18 runtime services, 25 contract packages, 10 edge functions, 13 generated registries, 24 scripts, and a full security directory. Below are the gaps found and fixes needed.

---

## Findings

### 1. Missing Edge Function Test Files
The test file `src/test/scripts-validation.test.ts` expects all 5 core edge functions to have `index_test.ts` files. Currently missing:
- `supabase/functions/agent-executor/index_test.ts`
- `supabase/functions/agent-heartbeat/index_test.ts`
- `supabase/functions/chat-advisor/index_test.ts`
- `supabase/functions/file-ingestion/index_test.ts`
- `supabase/functions/self-healing/index_test.ts`

**Fix**: Create minimal test stubs for each, following the pattern from `brain-core/index_test.ts`.

### 2. Database Schema Only Has 2 Tables
`src/integrations/supabase/types.ts` only defines `digital_twins` and `playbook_metrics`. Many services reference tables like `connector_configs`, `workflow_runs`, `incidents` etc. in edge functions. These likely exist in Supabase but the generated types are incomplete.

**Fix**: The types file is auto-generated by Supabase — no manual fix needed unless we want to add missing migrations. The edge functions use `any` typing which works at runtime.

### 3. `supabase/config.toml` is Minimal
Only has `project_id`. Missing function-level configs for all 10 edge functions.

**Fix**: Add `[functions.<name>]` entries with `verify_jwt = false` for each edge function.

### 4. Console Warning: forwardRef on Navigate
`ProtectedRoute` and `PublicRoute` trigger React warnings about function components receiving refs.

**Fix**: Harmless warning from React Router internals — no action needed.

### 5. Route Test Expectations May Fail
`src/test/route-coverage.test.ts` expects `path="/store/analytics"` — this route exists. But it also checks for `const StoreAnalyticsPage = lazy(` which exists. All lazy imports checked appear present. The test expects 80+ routes and the app has 150+. This should pass.

### 6. Duplicate Type Definitions
`src/lib/internal-agents/types.ts` and `src/packages/internal-agent-config/types.ts` define identical types. Not a blocker but creates maintenance risk.

**Fix**: Make `src/lib/internal-agents/types.ts` re-export from `src/packages/internal-agent-config/types.ts` to have a single source of truth.

## Implementation Steps

### Step 1: Create 5 missing edge function test files
Create `index_test.ts` for `agent-executor`, `agent-heartbeat`, `chat-advisor`, `file-ingestion`, and `self-healing` with basic health-check tests.

### Step 2: Expand `supabase/config.toml`
Add function entries for all 10 edge functions with `verify_jwt = false`.

### Step 3: Deduplicate internal-agent types
Update `src/lib/internal-agents/types.ts` to re-export from the canonical package location while keeping its extra runtime types (`AgentRuntimeState`, `AgentActionRecord`, etc.).

### Step 4: Verify build compiles cleanly
Run a build check to confirm no TypeScript errors or broken imports prevent deployment.

## Technical Details

- **Edge function test stubs** will import dotenv, call the function endpoint, and assert a 200/401 response.
- **Config.toml entries** follow the pattern: `[functions.name]` with `verify_jwt = false` since JWT is validated in code.
- **Type dedup** keeps the runtime-only types in `src/lib/internal-agents/types.ts` but re-exports shared types from the package.
