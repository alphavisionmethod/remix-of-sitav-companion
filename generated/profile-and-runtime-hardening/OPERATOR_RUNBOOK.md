## TL;DR — npm scripts

| Script | When to run |
|---|---|
| `npm run hardening:verify` | **CI / pre-commit** — runs drift + attestation gates only (fast) |
| `npm run hardening:gates` | **CI** — runs all 10 hardening gates via the orchestrator |
| `npm run hardening:release` | **Release pipeline** — full hardening + master aggregator |
| `npm run hardening:evidence` | After any structural code change (routes, apps, mobile features) |
| `npm run hardening:seal` | After approved structural change — re-baseline the GREEN surface |
| `npm run hardening:sign` | After re-seal — sign the new baseline |
| `npm run hardening:reseal` | **One-shot** — evidence + seal + sign + verify (use after PR merge) |

## The 10 Block-Level Gates

| # | Gate | Detects |
|---|---|---|
| 1 | `launcher-registry-completeness` | Apps registered in `APP_PLANE_MAP` but missing from launcher/profile/route |
| 2 | `app-profile-matrix` | Drift between `APP_PLANE_MAP.profiles[]` and `os/profiles/*.json allowedApps[]` |
| 3 | `hidden-app-routes` | Top-level shell-mounted routes with no registry entry |
| 4 | `mobile-capability-truth` | Mobile features marked "live" without real persistence/auth backing |
| 5 | `profile-route-coverage` | Routes whose plane isn't allowed by any profile manifest |
| 6 | `command-palette-profile-leakage` | Operator-only entries surfacing in user-profile palette |
| 7 | `shared-component-profile-pollution` | `src/components/`, `src/shell-runtime/` importing from `src/admin/**` |
| 8 | `route-guard-coverage` | Admin-plane routes without `AdminRoute` / `PermissionGatedRoute` |
| 9 | `profile-runtime-baseline-drift` | Surface expansion vs sealed baseline (Phase H) |
| 10 | `profile-runtime-attestation` | HMAC tamper detection on baseline + 4 evidence files (Phase I) |

## Common Workflows

### 1. Routine pre-commit verification

```bash
npm run hardening:verify
```

Runs drift + attestation. Fast. No side effects.

### 2. After adding a new app to `APP_PLANE_MAP`

```bash
# 1. Update os/profiles/{user,operator}.profile.json allowedApps[] to match
# 2. Run full reseal:
npm run hardening:reseal
# 3. Commit the modified baseline.sealed.json + attestation.signed.json
```

### 3. After adding a new admin route

```bash
# 1. Wrap the route with <AdminRoute> or <PermissionGatedRoute>
# 2. Run gates to confirm guard detected:
npm run hardening:gates
# 3. Reseal the baseline:
npm run hardening:reseal
```

### 4. CI failure: "TAMPERING DETECTED"

```bash
# 1. Inspect which file's digest changed:
cat generated/profile-runtime-attestation.json | jq '.digestMismatches'
# 2. Review git diff for that file
# 3. If intentional (e.g., evidence regenerated by approved code change):
npm run hardening:reseal
# 4. If NOT intentional: investigate. Someone manually edited a sealed artifact.
```

### 5. CI failure: "baseline-drift FAIL"

```bash
# 1. Inspect the drift:
cat generated/profile-runtime-baseline-drift.json | jq '.drift, .hardFailures'
# 2. Hard failure (new unguarded admin route, mobile regression): fix root cause
# 3. Soft drift (additive): npm run hardening:reseal
```

## Production HMAC Key Setup

For real deployments, set a secure HMAC key from your secret store:

```bash
export SITA_HARDENING_HMAC_KEY="$(openssl rand -hex 32)"
npm run hardening:sign
```

The dev key file (`generated/profile-and-runtime-hardening/.sita-hmac-dev.key`) is for local development only.

**Recommended `.gitignore` additions for prod:**
```
generated/profile-and-runtime-hardening/.sita-hmac-dev.key
```

(The dev key is checked in here so CI runs out-of-the-box; rotate it before production.)
