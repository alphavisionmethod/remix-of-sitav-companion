# iOS Native Runtime — Operator Runbook

> **TL;DR:** You don't need a Mac. One GitHub Actions click generates the entire
> production-grade iOS project. ~10 minutes later, a PR appears. Merge it. Done.

---

## How the iOS pipeline is structured

```
┌─────────────────────────────┐    ┌──────────────────────────────┐    ┌─────────────────────┐
│ Lovable sandbox (Linux)     │    │ macos-14 GitHub runner       │    │ macos-14 runner     │
│                             │    │                              │    │                     │
│ • Capacitor JS plugins      │ →  │ • npx cap add ios            │ →  │ • xcodebuild archive│
│ • src/lib/mobile-platform/  │    │ • Overlay ios-templates/     │    │ • Sign with         │
│ • ios-templates/ (hardened) │    │ • pod install (workspace)    │    │   provisioning      │
│ • Workflows + scripts       │    │ • Smoke build (simulator)    │    │ • Export IPA        │
│                             │    │ • PR or artifact             │    │ • Upload to         │
│                             │    │                              │    │   TestFlight        │
└─────────────────────────────┘    └──────────────────────────────┘    └─────────────────────┘
        ✅ Done by Lovable                ▲ ios-bootstrap.yml                 ▲ release-ios.yml
                                          (run once)                         (run on each release)
```

## Why this architecture?

The Lovable sandbox runs Linux. `App.xcworkspace` and `App.xcodeproj` are macOS-specific
binary plists that **must** be generated by Capacitor + CocoaPods on a Mac. Faking them
means a broken build the first time you try to sign anything.

So we **pre-stage** every plain-text override (Info.plist, entitlements, privacy manifest,
launch storyboard, Podfile, app icons) in `ios-templates/`, and let CI generate the
binary parts on a real Mac — for free, in the cloud.

## Step 1 — Bootstrap the native project (once)

1. Open **GitHub Actions** → **iOS · Bootstrap Native Runtime**
2. Click **Run workflow**
3. Inputs:
   - `commit_back: true` — opens a PR with the generated `ios/` tree
   - `branch_name: ios/bootstrap-native-runtime` (default)
4. Wait ~10 minutes
5. Review and **merge the PR**

That's it. Your repo now contains a real, hardened, production-grade iOS project.

### What you can verify after merge

| File | Why it matters |
|---|---|
| `ios/App/App.xcworkspace` | The real CocoaPods workspace (binary plist) |
| `ios/App/App.xcodeproj` | Xcode project (binary plist) |
| `ios/App/Podfile.lock` | Pinned native pod versions |
| `ios/App/App/Info.plist` | All permission usage strings |
| `ios/App/App/App.entitlements` | Keychain, associated domains, App Attest |
| `ios/App/App/PrivacyInfo.xcprivacy` | Apple privacy manifest |
| `ios/App/App/Assets.xcassets/AppIcon.appiconset/` | 14 icon sizes derived from 1024 master |

## Step 2 — Configure signing secrets (once)

In **GitHub repo → Settings → Secrets and variables → Actions**, add:

| Secret | Where to find it |
|---|---|
| `IOS_TEAM_ID` | Apple Developer → Membership → Team ID (10 chars) |
| `IOS_BUNDLE_ID` | Reverse-DNS, registered as App ID. Example: `com.sita.os` |
| `IOS_PROVISIONING_PROFILE` | Apple Developer → Profiles → download `.mobileprovision`, base64-encode |
| `IOS_SIGNING_CERTIFICATE` | Distribution certificate `.p12`, base64-encode |

> **Apple Developer Program membership ($99/yr) required** to obtain these. Until you fund
> it, `release-ios.yml` will refuse to run in `signed` mode and fail fast with a clear
> message. Unsigned-debug mode still works for verification.

---

## Step 3 — Sign and ship (every release)

1. Open **GitHub Actions** → **Release · iOS**
2. **Run workflow** with `mode: signed`
3. ~15 minutes later, IPA drops as artifact `ios-ipa`

For TestFlight upload, see the optional `Upload to App Store Connect` follow-up step
in the runbook below.

## Local Mac path (optional)

If you happen to have a Mac, you can bootstrap locally instead of via CI:

```bash
bash scripts/ios/bootstrap.sh
open ios/App/App.xcworkspace
```

This requires: macOS, Xcode 15+, Node 20+, CocoaPods (`sudo gem install cocoapods`).

## Troubleshooting

### `pod install` fails with "no such file or directory: @capacitor/ios"
You skipped `npm ci`. The Podfile resolves pods relative to `node_modules/`. Re-run
the bootstrap workflow from the start.

### Workflow says "ios/App/App.xcworkspace already exists"
That's expected on the second run. The workflow refreshes templates only and
re-runs `pod install`. If you want a clean regenerate, delete `ios/` first
(in a fresh branch) and re-run.

### `xcodebuild` exits with "No signing certificate matching team ID"
Your `IOS_PROVISIONING_PROFILE` doesn't match `IOS_TEAM_ID`. Re-export the profile
from Apple Developer for the correct team.

### Bundle ID rejected as placeholder
`build-ios.sh` refuses to sign with `app.lovable.*`. Set `IOS_BUNDLE_ID` to a real
reverse-DNS string registered as an App ID in your Apple Developer account.

### APNs push not working
Expected — APNs is deferred until Apple Developer Program membership is funded.
The plugin is installed and the registration code path is honest about returning
`null` until credentials land. To enable: uncomment `aps-environment` in
`ios-templates/App/App/App.entitlements`, re-run bootstrap, and add APNs key
secrets per `OS Deployment.md`.
