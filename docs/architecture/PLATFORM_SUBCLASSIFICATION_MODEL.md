# Platform Subclassification Model

**Status:** Adopted (Wave 0.5). **Authority:** Constitution Rules 27 & 28.

## Purpose

`src/platform/` was a flat list of 54 folders with no internal structure — at risk of becoming an "everything bucket." This model partitions it into **six canonical sub-classes** with explicit purpose, allowed dependencies, and validator enforcement.

## The six sub-classes

| Sub-class | Purpose | Allowed deps | Forbidden |
|---|---|---|---|
| `runtime-bridges` | Runtime/registry/integration/orchestration adapters (lowest layer) | `governance`, `identity-and-tenant` | All others |
| `identity-and-tenant` | Identity, auth, tenant, enterprise scoping | `governance`, `runtime-bridges` | `operator-control`, `intelligence`, `product-infrastructure` |
| `governance` | Trust, security, policy, audit, contracts, verification | `identity-and-tenant`, `runtime-bridges` | `operator-control`, `intelligence`, `product-infrastructure` |
| `intelligence` | AI capability layer, knowledge spine, advisors, boardroom | `governance`, `identity-and-tenant`, `runtime-bridges` | `operator-control`, `product-infrastructure` |
| `product-infrastructure` | Reusable product capability surfaces (files, notifications, search, app-platform, workspace) | All except `operator-control` | `operator-control` |
| `operator-control` | Operator/admin/owner UI shells (consumer surface) | All others | — |

**Universal rule (retained):** No platform sub-class may import from `src/modules/<pillar>/**` (Constitution Rule 2).

## Platform vs Admin boundary (Rule 28)

| Layer | Owns |
|---|---|
| `src/platform/<sub-class>/<system>/` | Reusable cross-pillar **capability** (services, models, primitives) |
| `src/admin/**` | Operator/admin/owner **UI** that consumes platform capability |

`src/platform/admin/` (151 files of admin command palettes, sub-navs, shells) is currently dispositioned `relocate-future` to `src/admin/`. `src/admin/components/index.ts` re-exports it as a transitional shim. Wave 0.5 emits **advisory** warnings for these re-exports; the future Platform Relocation Wave converts them to **blocking**.

## Enforcement

- **Manifest:** `generated/manifests/platform-subclassification-map.json` (Rule 27)
- **Ratchet baseline:** `generated/manifests/platform-cross-subclass-baseline.json` (decrease-only)
- **Validator:** `scripts/architecture/check-platform-subclassification.ts` (foundation-tier, BLOCKING)
- **Mirror gate:** `scripts/architecture/checks/check-platform-anti-patterns.ts` (revives the previously-orphaned validator-gate-map entry)
- **CI:** `.github/workflows/foundation-gate.yml` step "Rule 27 — Platform subclassification (REQUIRED)"

## Future Platform Relocation Wave

Out of scope for Wave 0.5 (would re-seal Wave-10 attestation and move 700+ files). Each move requires:

1. Reverse-dependency proof recorded in `generated/manifests/safe-change-evidence-ledger.json` (Rule 24).
2. New attestation digest committed via `npx tsx scripts/architecture/wave-10-emit-attestation.ts` (Rule 19).
3. Updated `platform-cross-subclass-baseline.json` reflecting the new lower violation count.

**Proposed moves:**
- `src/platform/admin/**` → `src/admin/**` (collapse the duplicate admin home).
- `src/platform/sita/shell/**` → `src/platform/experience/shell/**` (product-infrastructure).
- `src/platform/sita/apps/**` → `src/platform/apps/**` (product-infrastructure).
- `src/platform/sita/{primitives,cards,badges}/**` → `src/components/primitives/**` (shared UI).
- `src/platform/sita/{shell-hud,sita-hud,jarvis}/**` → keep in `operator-control` as `src/platform/sita-hud/`.

## Amendment process

1. Open ADR under `docs/adr/`.
2. Update this file + `CLASSIFICATION` in the generator.
3. Re-emit the manifest. CI must remain green.
