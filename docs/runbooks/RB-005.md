# Runbook RB-005 — Payments / Authorization Incident

> Severity: **High**
> Kill switch: **KS-PAYMENTS-AUTH** (dual-admin approval required)
> Owner: Trust & Safety on-call
> Related: `docs/desktop/SIGNING.md` (no overlap), `docs/os/SUPPORT_BUNDLE.md`

End-to-end response procedure when payment authorization signals indicate
abuse, fraud, gateway failure, or a verified data-integrity event.

---

## 0 · When to invoke

Trigger this runbook when **any** of the following is observed:

- Spike (>3σ) in `payments.authorize` failures within a 5-minute window.
- Anomaly detector emits `payments-auth-anomaly` event.
- Customer support reports unauthorized charge.
- Gateway provider declares partial outage on status page.
- Internal classifier maps incident `(payments, timeout|fraud|chargeback)` to RB-005.

---

## 1 · Triage (within 5 min)

1. **Confirm reality** — open `/admin/health` → Payments tab. Cross-check
   provider status page (`status.stripe.com`, etc.).
2. **Pull recent audit** — open `/admin/audit-logs?action=payments.*` and
   filter to the last 60 minutes. Note unique user_ids affected.
3. **Decide scope** — single-user / cohort / global.

---

## 2 · Activate KS-PAYMENTS-AUTH (dual approval)

If scope is **cohort or global**, activate the kill switch:

1. Open `/admin/kill-switches` → KS-PAYMENTS-AUTH.
2. Click **Request Activation**. Provide a justification ≥ 20 chars.
3. A second admin must approve via `/admin/approvals` (queued in
   `kill_switch_approvals` table).
4. On approval, the switch flips and:
   - All `payments.authorize.*` capability calls return refused receipts
     (`POLICY_KILL_SWITCH_PAYMENTS_AUTH`).
   - The `payments-gateway` edge function short-circuits before reaching
     the provider.
   - User-facing surfaces show the "Payments paused — Trust & Safety review"
     banner.

**Auto-expire** is set to 6 hours; renew explicitly via the same UI.

---

## 3 · Containment

1. Disable affected user sessions (admin panel → Users → batch sign-out).
2. Revoke active payment-method tokens for the affected cohort via
   `/admin/users/:id/payment-tokens`.
3. If a single bad actor — flag the user `risk_band = 'critical'` and
   disable account.

---

## 4 · Investigation

Pull a forensic bundle:

```bash
sudo sita-ops support-bundle --include-payments --since=2h
```

Bundle includes:

- `payments_authorize_attempts` for the window
- `kill_switch_audit_log` entries
- `admin_action_audit` actions taken
- redacted payload samples

Hand to T&S investigator. Confirm with provider's fraud team if applicable.

---

## 5 · Recovery

1. Once root cause is mitigated:
   - Open `/admin/kill-switches` → KS-PAYMENTS-AUTH.
   - Click **Deactivate**. Provide an outcome justification.
   - Second admin approves the deactivation.
2. Run smoke test: `/admin/health/payments → Run synthetic authorization`.
3. Communicate via `/admin/users/notify` to affected cohort with the
   resolution notice template.

---

## 6 · Post-incident

Within 24 hours:

- File incident report in `/admin/incidents` (auto-linked to runbook).
- Update `kill_switch_audit_log` with outcome.
- If repeat pattern emerges, propose detector tuning to Trust & Safety lead.

---

The gate asserts presence of:
