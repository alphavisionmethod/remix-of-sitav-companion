## Why this exists

A platform of SITA's size requires **one authoritative answer** to "who owns what." The Bounded Context Registry is that answer. It maps every meaningful runtime artifact (route, service, edge function, table, journey, kill switch, runbook) to **exactly one** owning context. CI gates (`check-bounded-context-coverage`) prevent drift.

## Per-context schema

Every entry declares all 18 fields from the meta-architecture spec:

- `contextId`, `contextName`, `description`, `owner`, `primarySurface`
- `sourceOfTruth[]` — authoritative file/dir paths (must exist)
- `canonicalApis[]` — public API names
- `readModels[]` / `writeModels[]` — DB views and tables
- `externalDependencies[]` — third-party systems
- `edgeFunctions[]` — edge function names (must exist in `supabase/functions/`)
- `services[]` — canonical service IDs
- `tables[]` — DB table names (must exist in `public.*`)
- `tests[]` — test directory patterns
- `deploymentUnit` — physical deployment target
- `runtimeTiersSupported[]` — tiers where context runs
- `criticalJourneys[]` — golden-path journey IDs anchored here
- `killSwitches[]` — kill-switch IDs that affect this context
- `supportRunbooks[]` — runbook IDs covering this context's incidents

## CI Validation

`scripts/architecture/checks/check-bounded-context-coverage.ts` enforces:

1. Every `BoundedContextEntry.sourceOfTruth[]` path exists on disk.
2. Every `edgeFunctions[]` name has a real `supabase/functions/<name>/index.ts`.
3. Every `tables[]` name appears in `src/integrations/supabase/types.ts`.
4. Every `killSwitches[]`, `supportRunbooks[]`, `criticalJourneys[]` reference resolves.
5. Every edge function in `EDGE_FUNCTION_BOUNDED_CONTEXTS` maps to a registered context.

Failures **block CI**.
